# Mode: repurpose

One source, several outputs.

1. **Core message, once.** From the source (an article, a post, notes) extract: the single point, the raw material that supports it, the angle. If the source is the user's own published piece, keep its angle.
2. **Targets.** List the requested family and platform pairs, and the language when it changes. If the user said "everywhere", propose the pairs from their `enabled_families` and `enabled_platforms` and confirm.
3. **For each target:** merge profiles, draft with `roles/writer.md` using the core message as the chosen angle, lint, run the Reader critic only, apply one editor round, then the proofreader. Convert lists for the target: real lists on platforms that render them, the user's typed marker on plain-text platforms.
4. **Consistency check.** Same facts, same figures, same links across all outputs. No new claim appears in one output only.
5. **Deliver** the outputs one after another, each labelled with family and platform.

**Changing language.** Adapting the user's own piece into another language is writing, not translation. Keep the core message and the facts. Rewrite the anecdotes, idioms and examples so they work for that reader, and draft from the user's published pieces in the target language, plus the pack's "In another language" notes. With fewer than 3 examples in that language, say so in one line before the draft. The consistency check still applies: same facts, figures and links in both versions. A text the user only wants rendered word for word is a translation: out of scope.
